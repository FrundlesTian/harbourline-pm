\section{Audit schema}

Each audit row has the fields \code{id}, \code{ts}, \code{run_id}, \code{actor}, \code{actor_type}, \code{action}, \code{target_type}, \code{target_id}, \code{outcome} and \code{detail}, defined in \code{app/db.py:61-64}. The actor type is \texttt{agent}, \texttt{human} or \texttt{system}. The outcome is \texttt{ok}, \texttt{blocked}, \texttt{rejected}, \texttt{fallback} or \texttt{error}, and the detail is JSON. Each agent write calls \code{audit.log()}, see \code{app/audit.py:43-49}; PM writes are logged inside the guarded adapter in \code{app/pmtool.py:356-376}.

\section{Coverage check}

\begin{itemize}
\item Every PM issue has a \act{pm create} row: 92 issues, 92 rows. Evaluation test T30 checks the same rule: 92 rows for 92 issues in baseline mode, 118 for 118 in LLM mode.
\item No agent write to the PM tool happened before HC2 and HC3 were approved: rows \#31 onwards follow approvals \#2 and \#3.
\end{itemize}
