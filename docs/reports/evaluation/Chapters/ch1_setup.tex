\chapter{What was evaluated and how}
\label{ch:setup}

This report covers the MA6094 Capstone, Group~5, as of 14 November 2026. Team: Group~5, no team name. Evaluation owner: Qu Chengzhi, G2510533D.

The evaluation harness is \code{eval/run_eval.py}. It has 34 test cases, T01--T34, and computes five measures, set out in Chapter~\ref{ch:measures}. All results in this report come from the latest code on branch \code{main}. Quantifying such properties of an AI system before it is relied on corresponds to the Measure function of the NIST AI Risk Management Framework \parencite{nist2023airmf}.

\section{Isolation}
\begin{itemize}
  \item Each run uses a throw-away SQLite database, so the demo database is never touched.
  \item The PM tool is always the local mock board, which implements the same data contract as the Jira adapter. Jira is used only with \code{--jira}, and that was not used here.
\end{itemize}

\section{Fault injection and ground truth}
Planted Critic faults come from \code{eval/faults.py}. Brief-gap ground truth is \code{eval/gold_gaps.json}: 22 gaps the team identified in the brief.

\section{Tests check behaviour, not baseline IDs}
The first LLM-mode evaluation on 8 November 2026 passed 27 of 33 cases. Most failures came from checks that expected the IDs or counts of the curated baseline, such as WBS element \code{3.2.3}, risk R22, re-score targets R06 and R17, or exactly four flagged WBS candidates. A generated plan numbers its items differently. On 14 November 2026 these checks were rewritten to test the behaviour instead, and T34 was added for a memory defect found in review. Chapter~\ref{ch:defects} lists each change.
